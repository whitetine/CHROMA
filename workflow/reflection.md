# 階段反思草案

來源取得曾有一次存取異常，Windows 單元測試有五次同根因編碼錯誤。編碼問題最集中，但不是五種獨立錯誤。將正文可讀性檢查前移至候選審查，UTF-8 檢查前移至程式靜態檢查。Graph V2 保留 V1 歷史並新增兩個閘門。前者尚未對新來源重測，後者見 execution-log。最終反思待 HTML 實測。

## Phase 5 反思（2026-11-24）
- 有效：把 Wiki 轉成純資料並禁止 innerHTML，使「Wiki 是唯一知識來源」可被驗證器比對（資料不同步即 FAIL）。color-utils 同時供瀏覽器與 Node 測試使用，21 項色彩數學測試首次即通過。
- 錯誤集中在版面而非色彩計算：ERR-004 的四項溢出都是 CSS grid／動畫細節；ERR-005 的六項問題全部只在截圖審查中被發現，其中「原生片段捲動」是程式行為問題，現已有回歸檢查。
- 驗證器本身也會出錯（ERR-003，兩次重試）；新驗證器應先以反例測試證明它會失敗，再信任其 PASS。
- 前移候選（未修改 Graph，留待 Phase 6 依證據決定）：在瀏覽器功能測試前加入「多寬度截圖＋水平溢出」檢查；把截圖人工／LLM 審查列為正式節點。
- 限制：只在 Windows Chrome 測試；觸控、螢幕閱讀器、其他瀏覽器與 Linux 皆 NOT_RUN；設計對照與情緒聯想未經使用者研究。


## Phase 6 最終作業反思（2026-11-24）

依 error-log 的 ERR-001～ERR-008 與 execution-log 撰寫；數字皆來自實際紀錄。

### 1. 哪個節點最常發生錯誤？
- 以錯誤紀錄數計：**HTML 生成後的前端驗證段落**最多。瀏覽器測試／截圖視覺審查有 3 筆（ERR-004、ERR-005、ERR-007），前端驗證器本身 2 筆（ERR-003、ERR-006），新測試腳本 1 筆（ERR-008）；來源擷取（ERR-001）與 Python 單元測試（ERR-002）各 1 筆。
- 以個別問題數計：**截圖視覺審查**最多，ERR-005 有 6 項、ERR-007 有 4 項 V3 繪製缺陷。
- 以單次失敗數計：ERR-002 一次造成 5 個 ERROR，但只有單一根因（CP950），不是 5 種錯誤。

### 2. 發現問題後，將檢查往前移至哪個節點？
| 錯誤 | 前移至 |
|---|---|
| ERR-001 | 來源候選階段的「正文可讀性預檢」（V2） |
| ERR-002 | 程式生成後、單元測試前的「UTF-8 靜態檢查」（V2） |
| ERR-003、ERR-006 | 信任前端驗證結果之前的「驗證器正常及異常測試」（V3；unittest 內含基準與反例） |
| ERR-004 | 瀏覽器功能測試前的「多寬度響應式與水平溢出」（V3；目前為流程規範，腳本尚未拆成獨立先行步驟） |
| ERR-005、ERR-007 | 無法前移到截圖之前；改為發現後「新增自動回歸檢查」，例如捲動檢查與圖形重疊檢查，讓同類問題下次由自動測試攔截（V3） |

### 3. 是否修改 Workflow Graph？為什麼？
是。建立 Graph V3，V1、V2 保留。原因：Phase 5 的錯誤集中在 V2 只有一個「瀏覽器測試」節點的前端段落，無法表達三種不同的回退去向：
- 驗證器錯誤應返回驗證規則，而不是網站；
- 版面錯誤應返回 CSS／SVG；
- 視覺問題應同時轉成回歸檢查。

V3 只依 ERR-003～ERR-006 的證據細化該段落，上游節點未變。V3 尚未從頭完整重跑；Phase 6 僅實際執行其前端段落，並觸發一次 Y→X→T 迴圈（ERR-007）。

### 4. 哪些錯誤是自動化測試發現的？
- ERR-002：Python 單元測試，使用者 Windows 環境。
- ERR-003：validate_frontend.py 首次基準執行。
- ERR-004：瀏覽器測試的水平溢出斷言。
- ERR-006：validate_frontend.py 與 test_baseline。
- ERR-008：子路徑測試腳本自身崩潰。
- V1／V2 既有標籤重疊：Phase 6 新增的圖形重疊回歸檢查。

ERR-001 則是在來源擷取過程中由 403 回應發現，不屬於測試。

### 5. 哪些錯誤需要實際截圖或人工視覺審查才能發現？
- ERR-005 全部 6 項：標題被藝術圖覆蓋、裝飾 SVG 文字裁切、首次載入 scrollY=58、色輪標籤裁切、Graph 標籤框過寬、截圖拍在淡入中途。當時 33/33 自動檢查全部通過，這些問題仍然存在。
- ERR-007 的 Graph V3 繪製缺陷：當時 35/35 全部通過。
- 兩次都是先由截圖發現，再補上自動回歸檢查。結論：自動檢查只能驗證已被想到的條件，截圖審查應保留為正式節點。本專案的「視覺審查」由 LLM 檢視截圖，使用者已於 Phase 5 人工確認成果，但並非每張證據截圖都經人工逐一審查。
